# Спецификация REST API: Система «АвтоСклад»

**Базовый URL:** `/api/v1`
**Формат данных:** `application/json`
**Авторизация:** Bearer Token (JWT) в заголовке `Authorization: Bearer <token>` *(опционально, если планируется авторизация)*

---

## 1. Справочник товаров и остатки (Stock)

### 1.1 Получить список товаров (Остатки)
`GET /products`

Возвращает список товаров с учетом фильтров.

**Query-параметры:**
* `search` (string, опц.) — поиск по артикулу, бренду или названию.
* `type` (string, опц.) — фильтр по типу: `real` (реальные) или `phantom` (фантомы).
* `availability` (string, опц.) — фильтр по наличию: `in` (> 0) или `out` (0).

**Успешный ответ (200 OK):**
```json
{
  "data": [
    {
      "id": "uuid",
      "article": "L06L109259E",
      "brand": "VAG",
      "name": "Магнит клапана фазорегулятора",
      "qty": 15,
      "location": "Стеллаж А-12",
      "comment": "Ходовой товар",
      "type": "real",
      "parentId": null,
      "phantoms": [
        { "sku": "06L109259a", "price": 1200 }
      ]
    }
  ],
  "total": 1
}
```

### 1.2 Обновить карточку товара
`PATCH /products/:id`

Обновляет полку, комментарий или другие текстовые поля товара (без изменения остатков!).

**Тело запроса (Request Body):**
```json
{
  "location": "Стеллаж А-15",
  "comment": "Переместили"
}
```

### 1.3 Управление фантомами (Кросс-номерами)
`POST /products/:id/phantoms` — Добавить фантом к реальному товару.
```json
{
  "sku": "06L109259b",
  "price": 1150
}
```

`DELETE /products/:id/phantoms/:sku` — Удалить привязку фантома.

## 2. Справочники контрагентов (Dictionaries)

### 2.1 Поставщики (Suppliers)
`GET /suppliers` — Получить список всех поставщиков.
`POST /suppliers` — Добавить нового поставщика.
**Тело запроса:**
```json
{
  "name": "ООО Ромашка"
}
```

### 2.2 Покупатели (Clients)
`GET /clients` — Получить список всех покупателей.
`POST /clients` — Добавить нового покупателя.
**Тело запроса:**
```json
{
  "name": "Иван (Розница)"
}
```

## 3. Движение товара (Транзакции)

*Примечание для бэкендера: Фронтенд сам парсит Excel, дает пользователю настроить колонки и отправляет на этот эндпоинт уже чистый массив объектов.*

### 3.1 Провести приход товара (Income)
`POST /transactions/income`

Создает документ прихода и **увеличивает** остатки на складе. Если товара с таким артикулом и брендом нет в базе — бэкенд должен создать новую карточку товара.

**Тело запроса:**
```json
{
  "supplierId": "uuid",
  "items": [
    {
      "article": "L06L109259E",
      "brand": "VAG",
      "name": "Магнит клапана фазорегулятора",
      "qty": 50,
      "purchasePrice": 1200
    }
  ]
}
```
**Успешный ответ (201 Created):**
```json
{
  "transactionId": "uuid",
  "message": "Приход успешно проведен, остатки обновлены"
}
```

### 3.2 Провести списание / расход (Expense)
`POST /transactions/expense`

Создает документ расхода и **уменьшает** остатки на складе. Бэкенд должен проверить, хватает ли товара на складе (защита от отрицательных остатков).

**Тело запроса:**
```json
{
  "clientId": "uuid",
  "items": [
    {
      "article": "L06L109259E",
      "shipQty": 10,
      "sellingPrice": 1500
    }
  ]
}
```

## 4. Отчеты и Экспорт (Reports & Export)

### 4.1 Отчет: Дефицит (Товары, которых нет в наличии)
`GET /reports/deficit`
Возвращает JSON со списком товаров, где `qty <= 0`.
*(Для выгрузки в Excel можно добавить query-параметр `?format=excel`, тогда бэкенд вернет файл `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`)*.

### 4.2 Отчет: Хиты продаж
`GET /reports/top-sellers`
Возвращает список товаров, отсортированных по количеству списаний (продаж) за выбранный период.
**Query-параметры:** `startDate`, `endDate`.

### 4.3 Генерация прайс-листа
`GET /export/price-list`
Бэкенд генерирует актуальный прайс-лист (Excel-файл) на основе текущих остатков и цен (включая цены фантомов) и отдает его файлом на скачивание.

---

### 💡 Рекомендации для Backend-разработчика:
1. **Транзакции БД:** Эндпоинты `/transactions/income` и `/transactions/expense` должны выполняться строго в транзакциях базы данных (ACID), чтобы при ошибке сохранения одного товара не сломались общие остатки.
2. **Связь Фантомов:** При поиске товара по артикулу (например, при списании), бэкенд должен искать совпадение как по основному `article`, так и по `sku` в таблице фантомов. Если найден фантом, списание происходит с остатков его родительского (реального) товара.
3. **Soft Delete:** Для товаров и контрагентов лучше использовать "мягкое удаление" (флаг `is_deleted = true`), чтобы не ломать историю старых накладных.

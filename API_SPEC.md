# Спецификация REST API: Система «АвтоСклад» (Нормализованная архитектура)

**Базовый URL:** `/api/v1`
**Формат данных:** `application/json`
**Авторизация:** Bearer Token (JWT) в заголовке `Authorization: Bearer <token>` *(опционально)*

---

## 1. Справочник Номенклатуры (Catalog)
Хранит **только статические данные** товаров. Никаких цен и остатков здесь быть не должно.

### 1.1 Получить список номенклатуры
`GET /catalog`

**Query-параметры:**
* `search` (string) — поиск по артикулу, бренду или названию.
* `type` (string) — фильтр по типу: `real` (реальные) или `phantom` (фантомы/кроссы).
* `parentId` (string) — получить все фантомы конкретного товара.

**Успешный ответ (200 OK):**
```json
{
  "data": [
    {
      "id": "uuid-1",
      "article": "L06L109259E",
      "brand": "VAG",
      "name": "Магнит клапана фазорегулятора",
      "location": "Стеллаж А-12",
      "comment": "Ходовой товар",
      "type": "real",
      "parentId": null
    },
    {
      "id": "uuid-2",
      "article": "06L109259a",
      "brand": "VAG",
      "name": "Магнит клапана (кросс)",
      "location": null,
      "comment": null,
      "type": "phantom",
      "parentId": "uuid-1"
    }
  ],
  "total": 2
}
```

### 1.2 Создать товар или фантом
`POST /catalog`

**Тело запроса:**
```json
{
  "article": "L06L109259E",
  "brand": "VAG",
  "name": "Магнит клапана",
  "location": "Стеллаж А-12",
  "type": "real" // или "phantom" с указанием "parentId"
}
```

### 1.3 Обновить карточку товара
`PATCH /catalog/:id`
Обновляет полку, комментарий или другие текстовые поля.

## 2. Регистр Остатков (Stock)
Связывает ID товара с текущим физическим наличием на складе.

### 2.1 Получить текущие остатки
`GET /stock`

**Успешный ответ:**
```json
{
  "data": [
    {
      "productId": "uuid-1",
      "quantity": 15
    }
  ]
}
```
*(Примечание: Остаток фантомов равен остатку их `parentId`, бэкенд может возвращать их вычисляемо, либо фронтенд мапит их сам).*

---

## 3. Регистр Цен (Pricing)
Отдельная сущность для хранения закупочных и продажных цен.

### 3.1 Получить цены
`GET /prices`

**Успешный ответ:**
```json
{
  "data": [
    {
      "productId": "uuid-1",
      "purchasePrice": 1200,
      "sellingPrice": 1500
    },
    {
      "productId": "uuid-2", // Фантом может иметь свою цену продажи
      "purchasePrice": null,
      "sellingPrice": 1400
    }
  ]
}
```

### 3.2 Установить/обновить цены вручную
`PUT /prices/:productId`

**Тело запроса:**
```json
{
  "purchasePrice": 1200,
  "sellingPrice": 1500
}
```

---

## 4. Справочник Контрагентов (Partners)
Единый справочник для поставщиков и покупателей.

### 4.1 Получить список контрагентов
`GET /partners`
**Query-параметры:** `type` (`supplier` | `client` | `all`)

### 4.2 Добавить контрагента
`POST /partners`
```json
{
  "name": "ООО Ромашка",
  "type": "supplier"
}
```

## 5. Документы и Движение товара (Documents)
Приход и расход оформляются документами. Проведение документа автоматически делает движения по регистрам (Остатки и Цены).

### 5.1 Получить список документов
`GET /documents`
**Query-параметры:** `type` (`income` | `expense`), `startDate`, `endDate`

### 5.2 Создать и провести документ (Приход / Расход)
`POST /documents`

Создает документ и **автоматически обновляет регистры**.
*   **Income (Приход):** Увеличивает `quantity` в `Stock` и обновляет `purchasePrice` в `Pricing`.
*   **Expense (Расход):** Уменьшает `quantity` в `Stock` (с проверкой на отрицательные остатки).

**Тело запроса:**
```json
{
  "type": "income",
  "date": "2026-03-19T12:00:00Z",
  "partnerId": "uuid-partner",
  "items": [
    {
      "productId": "uuid-1",
      "quantity": 50,
      "price": 1200
    }
  ]
}
```

**Успешный ответ (201 Created):**
```json
{
  "documentId": "uuid-doc",
  "message": "Документ проведен, регистры обновлены"
}
```

## 6. Сводные данные (Views / Reports)
Для удобства фронтенда, чтобы не делать сложные JOIN-ы на клиенте для таблиц.

### 6.1 Получить сводную карточку товаров (ProductView)
`GET /views/products`

Возвращает "склеенные" данные: Номенклатура + Остаток + Цены. Это основной эндпоинт для отображения таблиц на фронтенде.

**Query-параметры:**
* `search` (string)
* `availability` (`in` | `out` | `all`)

**Успешный ответ:**
```json
{
  "data": [
    {
      "id": "uuid-1",
      "article": "L06L109259E",
      "brand": "VAG",
      "name": "Магнит клапана",
      "location": "Стеллаж А-12",
      "type": "real",
      "quantity": 15,
      "purchasePrice": 1200,
      "sellingPrice": 1500
    }
  ]
}
```

---

### 💡 Рекомендации для Backend-разработчика:
1. **Нормализация БД:** База данных должна состоять из таблиц: `catalog`, `stock`, `prices`, `partners`, `documents`, `document_rows`.
2. **Транзакции БД (ACID):** Эндпоинт `POST /documents` должен выполняться строго в транзакции. Запись шапки документа, строк документа, обновление остатков и цен должны либо примениться вместе, либо откатиться при ошибке (например, нехватке товара при расходе).
3. **Логика Фантомов (Кроссов):** Фантомы хранятся в таблице `catalog` с `type = 'phantom'` и заполненным `parentId`. При запросе остатков фантома (`GET /views/products`), бэкенд должен подтягивать `quantity` от его `parentId`. При этом продажная цена (`sellingPrice`) у фантома может быть своя (берется из таблицы `prices` по ID фантома).
4. **Soft Delete:** Для справочников (товары, контрагенты) используйте "мягкое удаление" (флаг `is_deleted = true`), чтобы не нарушать ссылочную целостность в уже проведенных исторических документах.
